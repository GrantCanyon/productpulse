Одна семантика для панели, CLI и API. Все суммы — целые центы USD. Машиночитаемая схема: openapi.json ↗.

Две независимые оси времени

start включается, end не включается: это время события occurred_at. as_of включает только квитанции с received_at ≤ as_of. Дата события может быть позже момента знания — она не отсекается скрытым правилом.

Даты периода: 2026-01-05 (полночь UTC) или ISO 8601 с поясом. Момент знания обязательно с поясом: 2026-03-09T00:00:00Z. Без as_of используются все известные доставки.

Из чего складывается ревизия

/api/compare строит оба среза из одной прочитанной истории. revision.ledger_changes содержит добавленные, исключённые и изменившиеся операции с точным вкладом в оплаты, отмены и чистую стоимость. revision.ledger_delta суммирует эти вклады.

В каждой стороне before/after доступны source_refs канонических квитанций. Причины следуют из наличия доставки, семантических исключений и смены источников, а не из предположений о бизнесе. revision.funnel_changes отдельно объясняет изменение сессий воронки.

Статусы доставки

accepted — первое принятое событие; duplicate — эквивалентный повтор; conflict — уже существующий ID с другим содержимым; invalid — неверная схема или JSON. Первое принятое содержимое не заменяется.

Семантические исключения в снимке отделены от карантина. Например, missing_predecessor может исчезнуть после доставки пропущенного бронирования.

Архивные снимки без пересчёта

Создание доступно только в CLI: productpulse snapshot-save --start 2026-01-05 --end 2026-03-02. Укажите ту же базу, что и у панели. Команда возвращает UUID и контрольные суммы. snapshot-list перечисляет сохранения; snapshot-export UUID --format csv --output saved.csv создаёт новый файл без перезаписи.

GET /api/snapshots — список metadata с offset/limit; /api/snapshots/{id} — проверенные сведения; /api/snapshots/{id}/report — точные JSON-байты; /api/snapshots/{id}/ledger.csv — точные CSV-байты. Ни один из этих методов не запускает проектор отчёта.

Перед выдачей проверяются SHA-256 обоих артефактов. Заголовки X-Snapshot-ID, X-Content-SHA256 и X-Snapshot-Fingerprint различают UUID, хеш точных байтов и смысловой отпечаток. JSON — UTF-8 без BOM, CSV — UTF-8 с BOM и CRLF. Неизвестный UUID: 404; неверный UUID: 400; повреждённое содержимое: 409. POST/DELETE не поддерживаются.

Архив не включает raw-журнал: ссылки на события не являются автономной копией исходников. SHA-256 не является цифровой подписью. В панели архивный режим явно отделён от живого отчёта.

Область фильтров и ошибки

Показатели, журнал, воронка и когорты используют период и сегмент. Качество доставки относится ко всей базе в выбранном срезе. Семантические исключения относятся к обработанной истории до end. Счётчики качества не обязаны совпадать с размером журнала.

Ответ 400 — недопустимый диапазон, дата или статус; 422 — пропущенные параметры или недопустимая пагинация; 503 — база недоступна. Сведения о подключении в ответ не включаются.

API не содержит операций записи и аутентификации. Предназначен для локальной демонстрации синтетических данных. Исходные квитанции видны каждому, кто получил доступ к порту.

Справочник работает без CDN и встроенных скриптов. Интерактивные Swagger UI и ReDoc отключены, чтобы сохранить строгую политику ресурсов.
